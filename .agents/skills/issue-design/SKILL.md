# Issue design

Describe the smallest complete approach that meets the criteria, its affected components or documents, interfaces and data, significant alternatives or tradeoffs, and failure/recovery behavior where relevant. Use existing project architecture and production flow; consult the applicable domain skills for visuals, sound, PlayCanvas or PixiJS. For creative changes establish the representative sequence and comparison conditions before extending it. Identify what evidence will distinguish success from partial completion. Avoid new rules and premature new frameworks; record decisions in existing issue artifacts when sufficient.

## Parallel work

When this stage has independent work that can safely proceed in parallel and delegation is permitted and available, start subagents for those tasks. Assign non-overlapping file ownership or read-only scope; identify the candidate version and expected evidence. Integrate and check their actual outputs under the delegation rules in `issue-delivery`. Continue sequentially where dependencies require it or delegation is unavailable. Avoid duplicate tasks and recursive delegation with no independent work.
