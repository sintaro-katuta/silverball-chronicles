# 時間・カット・音・光

根拠：[D2/D4/D5/D6、V1〜V4](sources.md)。ここで示すタイムライン設計は本作向けの提案。各機種共通の正解秒数は設定しない。

## 演出を「強度」だけで組まない

| 状態 | 主役・問い | 設計する変化 | 次の状態への出口 |
|---|---|---|---|
| 通常変動 | 図柄・保留 | 読める繰り返しと小さな異変 | 停止または発展 |
| 予告・リーチ | 何が起きそうか | 対象に局所的な変化、視線の移動 | 相手・発展先を示す |
| 戦闘 | どちらが優勢か | 引き・寄り・反応・攻撃の因果 | 決着の構え |
| 当落直前 | 次で結果が分かる | 運動や音の整理、短い間 | 衝撃と結果 |
| 当り | 何が成立したか | 図柄・文字・役物・音の同期 | BONUS画面 |
| ハズレ | 通常へ戻る | 余韻を収束させ、見やすく復帰 | 次の変動 |
| 復活 | 終わったと思った場面の変化 | 一度引いて別の動機から再開 | 勝利結果。全外れに使わない |
| RUSH | 残りの挑戦・連続する結果 | 通常とは違うテンポ・構図 | 当りまたは終了 |

通常／右打ちの緩急を重視する制作例がある（D2）が、「RUSHは常に短ければよい」とは限らない。既存のコース別テンポを確認し、長尺コースと高速コースを同じ演出秒数へ揃えない。

## 絵コンテの最小単位

各カットに `開始イベント / 長さの仮値 / 主役 / 画角 / 動作 / 文字 / 音 / 光・役物 / 次へのつなぎ` を書く。

例として覚醒なら、エネルギーの収束→主役のポーズ→技への移行を分ける。画像のスクロールはカメラ移動であり、腕を振る作画とは異なる。必要な動作が素材にないときは、画面揺れで完成を装わず素材差分または短い映像を選ぶ。

`cinematic.js` の秒数は現行コードから読む。旧レビューの18.5秒だけをコピーすると、その後追加されたリーチ入口等を落とす可能性がある。時間変更では表示だけでなく終了・一時停止・結果受け渡しまで確認する。

## カットインと文字の動き

本作への設計案：登場で注意を集め、保持で読ませ、退出で次の主役へ渡す。人物と背景の流線は同じ移動量に固定せず、前後関係が分かるようにする。V1のサンプルでは文字がキャラより前に配置され、流線・破片が奥行きを補う。動きをそのまま模倣する義務はない。

静止を入れる箇所にも理由を持たせる。毎カットで同じ溜め→揺れ→白フラッシュを繰り返さない。外れ後の大きな「失敗」ラベルは、既存のプレイ継続と混同するので安易に戻さない。

## 音と役物

P1の開発意図は、期待する瞬間の認識を助ける告知。音を大きくすることだけを対策にしない。

本作では以下を別の役割として設計する：通常の入賞音、予告、危機・溜め、攻撃の衝撃、当りの確定、報酬の余韻。確定音と先告知は意味を分ける。BGM・ボイス・効果音が同時に重要なら、優先度と音量を決める。

役物の到達と衝撃音、図柄確定と確定音を共通イベントで合わせる。予告で役物を使い切って当りの差を消さない。D6はパチスロの制作例なのでLED配置・ゲームフローは使わず、音に合わせて実表示を調整する原理だけを参照する。

音声の評価は、スマホの小スピーカーとイヤホンで別に行う。低音が再生されない端末でも開始の輪郭が分かるか、連続発音で耳障りにならないかを見る。音キューがログに出ることは、聴感の品質保証ではない。

## 好みと演出頻度

先告知・静かな通常時・バトル鑑賞・違和感などを一人の好みとして混ぜない。[好みの資料](player-preferences.md)を読む。カスタム追加が依頼されていない場合は、既存コースでテンポや強弱を調整する案から考える。
