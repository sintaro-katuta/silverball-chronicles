# Webで演出を成立させる

ここは既存コードを読んだうえでの実装指針。Unity/Unreal/After EffectsのAPIやプラグインをブラウザで使える前提にしない。AEの制作例はレイヤー・構図・時間の参考である。

## 表現と描画方式

| 必要な表現 | このプロジェクトでの第一候補 | 選択条件 |
|---|---|---|
| 持ち玉、設定、ポーズ、操作 | DOM/CSS | 読みやすさ・操作・フォーカスを維持 |
| 背景、顔、カットイン、斬撃 | 既存Canvasとローカル画像 | 既存 `battle.js` を使い、必要なら透過素材を追加 |
| 筐体・玉・釘・立体役物 | 既存Three.js scene | 材質・光・物理形状の整合が必要 |
| 立体の演出文字 | 既存 `title-art.js` | 実ジオメトリが有効な場面。小さい文字は画像等も比較 |
| 連続したキャラ作画 | 事前制作の短い動画／画像列 | 手描きの動作が必要で、素材・容量・再生同期を確保できる場合 |
| 告知・衝撃・ジングル | 既存Web Audio | 共通イベントと同期し、同時発音を管理 |

WebだからすべてCSSで作る必要はない。反対に、装飾一つごとに新しいWebGLコンテキストやライブラリを追加しない。既存方式で見え方が成立するかを先に比較する。

## 時計と結果

`main.js` の共通ゲーム時間、`cinematic.js` の演出時間を利用する。演出を独立した `setTimeout` の鎖で動かすと、ポーズ・速度変更・復帰とずれる。描画から経過時間を参照し、音イベントは一度だけ発火させる。

結果・R数・RUSH突入と、いつ表示するかを分離する。ロード失敗・動画終了・PUSHの押下で新しい結果を引かない。終了処理は重複しても報酬やラウンドを二重開始しないようにする。

動画を採用する場合は再生失敗、停止、復帰、末尾の静止、次シーンへの受け渡しを設計する。動画の `currentTime` とゲーム時間の扱いを明示し、音付き動画とWeb Audioで二重に同じ音を鳴らさない。

## ブラウザ・WebViewの制約

- 音はユーザー操作から開始・再開する。自動再生が拒否される可能性を扱う（W1）。既存の開始ボタンとミュートを使う。
- 非表示タブでは描画・タイマーが制限される（W2）。本作の非表示時ポーズを維持し、戻った瞬間に未再生の音をまとめて鳴らさない。
- 端末内で使う画像・音・フォントを同梱する。外部CDNや実行時生成APIへの依存を加えない。
- 小画面の実表示を基準にする。高解像度の書き出しが綺麗でも、台全体表示で文字が潰れる場合は造形・配置を直す。
- 全画面フラッシュはW3の条件を確認する。演出軽減では揺れ・閃光を下げ、結果の情報は残す。「3回以内」だけで安全と断定せず面積・赤色閃光等の条件も見る。

## 負荷の確認

60fpsは保証ではなく、必要なら設定する検証目標。端末・ブラウザ・DPR・同時玉数・場面を記録してフレーム時間を測る。高発射レートを持つ本作では、演出単独のデモだけで判断しない。

候補：画像の事前decode、使うシーン単位のロード、ジオメトリの再利用、見えない層の描画停止、効果の上限設定、端末別DPR調整。変更前に実際のボトルネックを確認する。低負荷化で削る順序は、細かな粒子・反射などから検討し、図柄の結果・音の発火・入力受付を欠落させない。

Three.jsの色空間・トーンマッピング等のAPIを変える際は、インストール済みバージョンと公式ドキュメントを確認する。今回、Three.js公式color-managementページは取得失敗のため、その内容を根拠とした設定値は採用していない。
