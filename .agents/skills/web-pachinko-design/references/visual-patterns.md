# 液晶の造形と画面構成

根拠IDは [sources.md](sources.md) を参照。以下の「本作への適用」は設計提案であり、人気の実証や採用済み仕様ではない。

## 表現の系統を選ぶ

| 系統 | 視覚上の役割 | 月影機関で検討する場所 | 失敗しやすい点 |
|---|---|---|---|
| 図柄主体 | 数字の識別と停止を見せる | 通常変動・リーチ入口 | 全景イラストの上で数字だけが小さく点滅する |
| 物語・バトル主体 | 対立と決着を見せる | 戦闘リーチ | 一枚絵に同じ揺れと粒子を重ね続ける |
| シンボル告知主体 | 小さな変化に意味を持たせる | 保留・予告の候補 | 常時点滅して変化の意味が消える |
| 決着・祝祭主体 | 成立した結果を強く見せる | 当り・RUSH突入 | 予告と当りが同じ画面・音量になる |

複数を混ぜてもよいが、同じ瞬間の主役を決める。V2/V3では場面により図柄・キャラクター・結果数字の占有が変わる。常に同じHUDの中身だけ差し替える構成に固定しない。

## 図柄・保留

制作上、図柄・保留・文字は別々に造形する対象である（D1）。本作では数字の輪郭、外周、表面、キャラクターとの重なりを分けて検討する。縦スクロールの途中、左右に縮小した状態、停止時のいずれでも識別できるかを見る。

通常図柄と演出中の小図柄で細部の量を変える。スマホ上では細い装飾を増やすより外形の差を優先する。保留は残数と対象の位置が分かる形にし、変化演出が消費・追加の表示を壊さないようにする。

## 演出文字

D3では文字の正面と側面の扱いを分け、縁の表現で立体感を作る例がある。本作への適用：

- 正面は読み取れる面を残し、側面・面取り・外縁で重さを作る。全面発光で字の穴を潰さない。
- 登場時の大きさと保持時の読みやすさを別々に設計する。巨大な文字をずっとキャラクターの顔に重ねない。
- 通常ラベル、台詞、期待を示す言葉、技名、確定結果で書体処理を使い分ける。
- `title-art.js` は既に実立体文字を描く。さらにCSSの影を積む前に、実際の小画面で面の白飛び・輪郭・欠けを調べる。
- 新しい日本語を入れる際は `title-glyphs.json` の字形を確認。欠字を空白のまま完成扱いしない。

## 色の意味

D2/D3は色の判別が制作上重要な点を説明する。本作では次の二つを分けて定義する。

1. **世界観**：月光、青鋼、銀、夜の背景など。存在するだけでは期待度を示さない。
2. **告知**：特定の保留・枠・文字の変化。どの状態で何を知らせるかを決める。

同じ銀・金でも、筐体の材質と演出予告を混同させない。虹色や専用音を確定に割り当てたなら、外れ側で同じ組合せを使わない。厳密な確率表を表示する場合は対象モードと条件を実装から確認する。

## 構図・奥行き

背景／登場人物／文字／前景効果／盤面という層の関係を決める。D3/V1の奥行き表現は候補であり、全部を常用する指示ではない。

本作での候補：通常は背景のディテールを抑えて図柄を読む。対決では相手の姿と距離、危機では被害や表情、覚醒では顔・手・武器などへ切り替える。決着は結果図柄へ視線を戻す。構図・動作・情報が変わることを確認する。

玉が液晶前を流れる本作では、細かい火花と玉を見分けられるかも確認する。役物が降りる場所、台詞、保留の表示位置を同時に設計する。

## 素材の発注単位

不足素材を「アニメっぽい画像」と発注しない。人物、表情、動作、画角、背景、前景、切り抜きの有無、画面内の安全領域を指定する。背景込み一枚絵では、切り抜きキャラクターが帯から飛び出す表現はそのまま作れない。

同じ人物の顔・衣装・武器・光源の整合を確認する。画像の枚数を増やす前に、相手の攻撃→主人公の反応→結果が読める組み合わせを作る。参考作品の名称や絵を置き換えただけのコピーにしない。

## 起きやすい問題と修正

| 観察できる問題 | 修正の方向 |
|---|---|
| 明るい枠と文字で液晶が白く見える | 主役以外の輝度を下げ、面と輪郭を戻す |
| 金色の大文字だが内容が伝わらない | 言葉を短くし、登場→保持→退出の保持を確認 |
| どの展開も同じ絵のズーム | 構図かアクションの足りない素材を特定する |
| 予告と当りの差が分からない | 最大の造形・発光・音の組合せを決着に残す |
| パチンコが小さなカード内に収まる | 操作部の実寸を守りながら盤面の表示領域を取り直す |
