# 共通パルス音色と2声のハーモニー

silverball-chroniclesで参照再現からオリジナル制作へ進めた選択肢。全効果音への既定ではなく、明るい電子音・確定音で試す共通プリセットの候補として使う。

## 評価された範囲

ユニコーン再現ではC（矩形波・鋸波）がB（元のFMをフレーズで再発音）より好まれた。Bも選択肢として残す。その学習から新しい打点・音程を設計した「月光開放」で、同じ音色の2声を重ねる案が「かなり良かった」、ハーモニーを1オクターブ下げた案も「結構好き」と評価され、低いハーモニー版が確定。単音の旋律への肯定と当たり音としての受入は分けて記録する。

## 共通音色の出発点

- 矩形波70%＋鋸波30%、矩形波幅35%、19倍音。
- 96kHzで合成し、130〜6000Hzのフィルター、共通の空間処理、48kHzへ変換。
- 両声とも同じプリセット。声ごと・区間ごとに別音色へ切り替えない。
- 内蔵の微小な5.7Hz音程変調、最後の保持へ追加±8cents・7.6Hzの変調。これは採用されたこの音の設定で、すべての新音に必要な値ではない。
- 47Hz AMを加えた別の試験は未評価。確定した方式に黙って混ぜない。

## 2声の設計

まず主旋律の打点・音長・一定音程を決め、ハーモニーの音程を声ごとに保存する。評価された案ではF# majorの音階に沿う上の3度を作り、その声を1オクターブ下へ置いた。最終の指定値は主旋律739.989Hz＋下の声466.164Hz。声の配分は主0.82／ハモ0.64。和音や音域は新しい用途・フレーズに合わせて決め、今回の音程列を全演出へ流用しない。

「細かく」は音程差、切替間隔、音数のどれを指すか分ける。今回、40〜68msで近い3音を反復した案は、速すぎる・同じ展開の反復と評価された。元の打点へ戻した異なる3つの展開は好まれ、その後の小変更は2音だけ足して検証した。複雑さや声の数を増やすこと自体を迫力の根拠にしない。

2声の混合を単音向けpYINへ入力しても、両声の音程を分離できない。valid率が0%になっても無音・音程なし・失敗とは扱わない。指定した両声の時間／Hz、スペクトログラム、同音量での試聴を併用する。必要なら各声の単独合成を内部解析用に保存し、混合からのF0だけで調整しない。

## 復旧した設計と再生成

この音の設定は [pulse-harmony-approved.json](../assets/pulse-harmony-approved.json) に復旧した。これはカスタム2声用の形式で、汎用render.pyのJSON形式とは異なる。[render_pulse.py](../scripts/render_pulse.py) は履歴から復旧した元コードを、単独スキルから実行できるよう入出力指定だけ再構成したもの。

```sh
<python> <skill-dir>/scripts/render_pulse.py --out <new-empty-directory>
# 別のオリジナルを設計する場合は設定のコピーを編集して渡す
<python> <skill-dir>/scripts/render_pulse.py --design <pulse-design.json> --out <new-empty-directory>
```

元のプロジェクト側の final/ 音声と設定は2026-10-16時点では見つからない。今回、復旧した設定とコードで6秒の音を再生成し、過去のWAVのSHA256（4d873b3468ce37244badef9b3dd22c6a0765ec4b163e553a5b03b3e7b352207c）との一致を確認した。過去の原ファイルを回収したのではなく同じファイルを再生成できた結果であり、新たな聴感受入や別環境一般の完全一致を保証しない。

今回の音程列を他の演出へ流用する規則にしない。ドラム・ベース追加版と最後の減衰試作の採否は [後続の試聴フィードバック](session-feedback.md) を読む。本編への接続と公開は別の依頼・受入。
