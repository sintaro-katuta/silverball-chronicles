# 音の高さの比較（librosa / pYIN）

「キーが低い」「音程が違う」を調べるときは、参照音と制作音のlibrosa STFTスペクトログラムと、pYINの基音時間変化を併用する。強いFFTピークを基音と決めない。スペクトログラムでは倍音・非整数のFM成分・ノイズ・打点を、pYINでは周期性が推定できる区間のF0を確認する。

## 範囲と条件

- まず全帯域のスペクトログラムと音を確認し、周期性がある最低成分、倍音列、想定される上下のオクターブから対象ごとにfmin/fmaxと理由を決める。合成の指定Hzと一致するよう探索範囲を狭めない。100–1400HzはユニコーンQ1の今回の範囲で、既定値ではない。候補が境界へ張り付く場合は範囲を再検討し、結果を上書きせず保存する。
- 参照と制作でSR、窓、hop、探索範囲、信頼度条件を揃える。切出し位置・対応時刻・ゲイン条件を記録する。短い音程切替は窓で混ざり、低い基音には長い窓が必要になるため、両方の時間分解能の限界を記す。
- 多声、声/BGMの混在、非整数FM、ノイズ、急な切替ではpYINが別の成分や下位倍音を追う場合がある。voiced probabilityは正しい基音の確率ではない。高い値でもスペクトログラム、合成仕様、試聴と照合し、説明できない区間を確定値扱いしない。
- unvoiced、低信頼、無音、境界などの推定不可はJSONでnull、グラフでは欠測として残す。補間、近傍値、FFT最大ピークで埋めない。追加で判定困難と判断した区間は時刻と理由を報告する。欠測率・両音で有効な区間の割合を併記する。
- 半音差を比較する場合は同時刻かつ両方の有効フレームだけに限定する。補助スクリプトは両音の有効率が10%未満なら半音差の要約を出さない。この閾値は今回の報告用ガードであり、10%以上なら音程が正しいという保証ではない。局所の値を全曲のキー、知覚上の高さ、再現品質の改善率に読み替えない。基音の差と、高い倍音による明るさの差を分ける。

## 実行

作業用Pythonに `librosa matplotlib`（numpy等は依存）を導入する。導入版は出力JSONに記録される。入力は同じ尺・対応する開始時刻の音。スクリプトは入力を変更せず、分析用にmonoへ平均しリサンプリングする。自動の時間伸縮・音量正規化はしない。チャンネルの位相打消しが疑われる場合は個別チャンネルでも調べる。

```sh
<python> <skill-dir>/scripts/pitch_compare.py \
  --audio reference=<reference.wav> --audio candidate=<candidate.wav> \
  --fmin <Hz> --fmax <Hz> --range-reason '<対象音に対する根拠>' \
  --out <empty-analysis-directory>
```

`--audio`で基準音も追加可能。既定は分析SR22050Hz、Hann4096、hop256（約11.6ms）、信頼度閾値0.8、RMS−60dBFS以上。4096窓は約186msで、瞬時の切替時刻の確定には粗い。少なくともfminの2周期を窓に含める。設定は対象と用途に応じて変え、変えた理由を残す。

出力：同じ時間・周波数・色尺度の `spectrograms.png`、欠測を保持した `f0.png`、各フレームのF0/null・voicing判定・確率・有効率・入力SHA256を含む `pitch-analysis.json`。スペクトログラムの色は全入力共通の最大値を基準にしたdBであり、音量差も反映する。音色だけを比較する場合は別の分析用コピーへ固定ゲインを適用してその値を記録する。

## 従来法との役割分担

従来のFFTピーク、scipy STFT、帯域エネルギー比は高速で、倍音の強さや音色を把握しやすい。一方、最大ピークをF0へ読み替えるとオクターブやFM側帯の誤認が起きる。librosaのスペクトログラムそのものが従来のSTFTより本質的に高精度になるわけではなく、主な利点は条件を揃えた再利用とpYINとの組合せにある。

pYINは周期性の候補と時間的連続性からF0とvoicingを推定し、最強の倍音だけに依存しない。一方、処理が重く、探索範囲・窓に影響され、複雑なSEでは欠測やオクターブ誤りが残る。両者を併用し、推定不可を維持する。

公式仕様：[librosa.pyin](https://librosa.org/doc/0.11.0/generated/librosa.pyin.html)、[STFT](https://librosa.org/doc/0.11.0/generated/librosa.stft.html)。実行版のAPIも確認する。

## 評価方法を監査するとき

「修正前」は今回の変更の直前のファイルか、別の旧候補かを明示し、SHA256と保存版で確かめる。同じ尺だけで場面と時刻の一致を保証せず、参照動画の切出し秒、合成の時間制御点、打点と周波数変化の対応を確認する。valid定義・閾値・分析版を表示する。

参照のF0推定率が低いときはF0だけで類似度を判断しない。valid率やvoicing probabilityを上げることを制作目標にしない。未推定は無音・0Hzではない。多声、ノイズ、非整数成分、探索範囲、窓、mono化の影響を、必要な感度分析で調べる。条件通過フレームも独立に正しいF0と確定したものではない。局所の誤差には共通validのフレーム数と割合、対応時刻、信頼性の限界を併記し、共通がなければ誤差をnullのまま残す。

同じ時間軸・周波数軸・色尺度のスペクトログラムに加え、RMSとmomentary LUFS等の音量包絡も比較する。帯域比が近くても、立上り、持続、減衰、成分の集中・多層の揺れが違えば改善を実証したと扱わない。持続音を強くしすぎた／響きを単純化した等は仮説として、参照にも存在する成分と録音背景を区別する。集中度・平坦度も品質の目標値にはしない。

音の修正を進める前の評価依頼では、元音と修正前を保持し、同一区間のLUFSを固定ゲインで揃えた試聴コピーを提供する。全尺を揃えても局所音量は違い得るので、指定区間は別途揃え、ゲイン値を記録する。LUFSは聴感を合わせる補助であり、採否は参考の特徴とゲームでの気持ちよさを試聴して判断する。解析器が検出しやすい単音を作ることを目的にしない。
