# クイズ・解説動画からの再現実験

スキル強化・参照の合成再現を依頼されたときに使う。録音の波形を分割して戻す方法と、新しい発振器・ノイズから合成する方法を区別する。ここで保存する学習対象はスキル手順・合成器・制御設定。モデル重みや方策を更新した場合には、対象モデル・報酬・訓練手順を別途記録する。

## 出題と解説を対応させる

1. 動画の機種名・演出名を答え表示で確認する。自動字幕は入口に使い、誤認識を正解ラベルにしない。映像のON AIRと波形の発音を照合する。
2. 最初の音と繰り返しを分け、音の前後を含む区間を秒で固定する。解説の声、出題の共通ジングル、カウント音、BGMを混ぜて、SEの倍音や余韻と誤認しない。厳密な分離ができない場合は未分離と記録する。
3. 出典URL、出題番号、解説への入口、切り出しの開始・終了秒、取得した録音のSHA256を保存する。全問の索引を作ったことと、全問の再現・聴感確認をしたことを区別する。

## 比較と候補探索

- 現在の合成器による基準案を先に保存する。追加した層・制御・設定だけを候補案へ反映する。
- 音量包絡だけ変更した案などを挟み、音量差や時間変化の一致が改善を支配していないか確かめる。候補案全体の差を、単一パラメーターの因果の証明にしない。
- `scripts/compare.py`は同じサンプルレート・同じ長さの参照と候補を比較する。L/R平均のmono、候補への1つの固定RMSゲイン、64対数帯域（40Hz〜16kHz）、2048点STFT、20ms RMSの包絡を使う。

```sh
<python> <skill-dir>/scripts/compare.py --reference <reference.wav> --candidate <candidate.wav> --out <comparison.json>
```

**最新の評価：** 第11・13問はユーザー試聴で旧方式が優位、今回の候補は不採用。第3問はユーザー判断で再現評価の対象外。今回のobjectiveは採否を決める指標として妥当性が確認できていない。数値が低い候補を「改良」と呼ばず、試作として提示する。

`objective = 0.7 * spectral_db_mae + 0.3 * envelope_db_mae`は今回の探索用代理指標。低いほどこの指標では近いが、聴覚モデルでも一致率でもない。種が固定されたノイズの位相や、知覚上重要な瞬間はこの指標だけでは評価できない。

- 候補探索は同じ参照に対する有限の範囲で行い、変更値と全候補の結果を残す。探索した値の境界が最良なら、必要に応じて次の範囲を再設計する。予算・試行数を明示し、際限なく増やさない。
- 完全に同じ信号と、ゲインだけ違う信号でobjectiveがほぼ0、時間をずらした信号で差が増えることを確認する。長さの違いを黙って切り捨てたり、時間伸縮で隠したりしない。
- 試聴用は参照・基準・候補を同じ区間・mono・固定RMSゲインで揃え、全音へ共通のピーク余裕を確保する。自動の瞬間正規化・圧縮は使わない。元のステレオや本番ゲインでの確認は別に残す。
- 同じ参照へのフィットは未知の音への一般化を証明しない。別の問題・別動画で確認し、ユーザーの聴感フィードバックは数値と別項目で保持する。

## 人の評価を受けた更新

今回の比較では数値順位と聴感順位が逆転した。数値は候補探索の補助に留め、入口、振動の質、音程と倍音の動き、余韻を同条件で試聴して採否を記録する。ユーザーが評価不能とした例は成功・改善率の集計から除外し、元の波形の測定自体が物理的に不可能だったという断定とは分ける。

[履歴から再構成した試聴フィードバック](../assets/reference-experiment-feedback.json)を実験設定と併せて読む。第11・13問の旧方式優先は今回の比較での選好で、旧方式全般の品質合格や本番採用を意味しない。参照の音質・混在音・切り出し・合成能力・評価指標のどこに原因があるかは未確定。今回の不一致だけで動画を悪い教材と断定しない。新しい評価指標は、聴感順位との対応を別の参照でも確かめてから採否に使う。

## 3例の失敗を受けた制作方針

改善実証0件、旧方式からの悪化2件、再現不足1件として扱う。既定は一音・一変更軸・基準音との比較。評価が済むまで別の音や共通化へ展開せず、低い数値の候補を品質の良い案として自動選択しない。新しい制御は実験扱い、今回のフィット設定は不採用の検査資料として保存する。複数同時の制作が原因だったという仮説の確認と、どの音響特性が不足していたかの切り分けはまだ必要。

## 動画の参照方法

YouTube直接再生は演出・内容の確認に使い、反復測定ではyt-dlpで保存した映像から対象区間を固定し、WAVへデコードする方法を検討する。映像が不要なら音声のみの取得でもよい。取得したvideo/audio形式、出典、区間、SHA256を残す。MP4は容器であり、保存・結合だけで音質が改善したとは扱わない。直接音声取得とMP4経由の音を比較するなら音声形式を揃え、再エンコードせず抽出したデータやデコードPCMの一致を確認する。ブラウザでの再生と保存音声の形式が同じだと未確認で決めない。
