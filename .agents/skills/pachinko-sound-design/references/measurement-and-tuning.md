# 測定の解釈と音の調整

## 再現性

入力JSONを既定値で解決した`design-resolved.json`と、設定・エンジン・レンダラーのSHA256を保存する。乱数seed、Python／numpy／scipy／FFmpegの版も記録する。同じseedでもイベント列や合成方式を変更すると波形は変わる。別環境のPCMまで無条件にbit一致するとは言わない。

`measurements.json.acceptance`は数値の検証状態と、ブラウザ・聴感・本編の状態を分ける。スクリプトの完了だけで他の項目をpassedへ書き換えない。

## 指標の意味

| 指標 | 用途・限界 |
|---|---|
| 積分LUFS | EBU系の重み付き音量。FFmpeg loudnormのinput値。書き出しへのloudnorm処理ではなく、固定ゲインの決定に使う |
| True peak | オーバーサンプルで推定したピーク。PCMの最大値とは異なる |
| PCM peak／クリップ数 | ファイル内の振幅。波形が収まっていても、音色の歪みがないことは証明しない |
| 400ms RMS最大 | 400ms窓、100ms hopの非重み付きRMS。LUFS momentaryではない。0.4秒未満は実際の長さで割る |
| Crest | peak/RMSのdB。高いと衝撃と持続部の差が大きいが、良し悪しの自動判定には使わない |
| 帯域エネルギー比 | チャンネルごとにSTFTのエネルギーを加算。20〜250／250〜2000／2000〜8000／8000〜20000Hz。全20Hz〜20kHz成分を分母にする |
| スペクトル重心 | 全フレームのSTFTエネルギーで重み付けした周波数。音程でも知覚上の明るさそのものでもない |
| `mono_loss_db` | ステレオ全サンプルRMSに対する、L/R平均のRMSの差。位相による消失の手掛かり。単純なL/R平均での評価で端末実測ではない |
| `active_end_60db_s` | 最大20ms RMSの−60dBより大きい最後のフレーム終端。SEの意味上の終了とは異なる |
| Stereo correlation | 全尺のL/R相関。片チャンネルが無音ならnull。高相関・低相関をそのまま品質へ読み替えない |

STFTは通常2048点Hann窓、hop512。短い音では窓を信号長以下へ縮める。短いSEのLUFS解析には末尾を最低1秒まで無音で埋める。出力音声そのものの長さは変えない。この窓条件を揃えず、短音と長音の数値を完全な聴感一致と扱わない。

## ゲイン調整

1. float中間音声のLUFSとtrue peakを測る。
2. `gain_db = min(target_lufs − input_lufs, ceiling − input_true_peak)`を適用する。
3. PCM24へ変換した後、もう一度測定する。コードは上限から0.15dBの計測丸め許容を設ける。
4. ピーク条件が先に当たれば、`peak_limited`と目標未達を残す。無断でリミッター、圧縮、各層の正規化を加えない。

全案のintegratedを揃えるのが常に良いとは限らない。衝撃と余韻の比率や尺が違う案では、一番重要な400ms区間を別途測って比較する方法もある。その際は重み付き音量かRMSか、窓の位置・長さ・適用ゲインを明記する。

## 調整を数値へ翻訳する

| フィードバック | 試す変更 | 確認するもの |
|---|---|---|
| 入口が弱い | impactとbodyの初期gain、attack、最初の音程差を1軸ずつ変える | 最初の打点が分かるか、ピーク条件で全体が下がっていないか |
| ヒューンが強すぎる | pitchカーブの連続変化を短くし、打点や一定音程の区間を増やす | 周波数図の傾き、短・長の区別、聴感 |
| 震動が足りない | flutter、rumbleのgain／Hzと保持長を変える | 低域比、スマホで本体が残るか、連続時の刺激 |
| 電子チャイムに寄りすぎる | fm_index／fm_ratioと金属層の配分を変える | 倍音の広がり、輪郭、刺さる帯域 |
| 最後の一打が弱い | 最終イベントの長さとgain、直前の間を変える | 最終打の認識、最終打より前を強くしすぎていないか |
| モノラルで細くなる | detune_centsを減らす、低い芯を中央に置く、層の相を見直す | mono_loss_dbと実際のモノラル試聴 |
| 余韻が次を隠す | release_s／decay_s、ringの長さとgain、イベント間の余白を変える | active_end、再発音間隔、聴感 |

この表は候補の探索方向で、因果の保証や自動合格ルールではない。数値を変えた案を同条件で試聴し、採用した設定だけを残す。

## ブラウザと本編

ローカルHTTPで試聴HTMLを開き、各WAV／MP3のデコード、全尺再生の終了、切替時に前の音が止まること、停止、保存を確認する。ブラウザの終了イベントは音がスピーカーから正しく鳴った証拠ではない。

本編接続では既存コードの発音窓を確認する。以前のsilverballの0.5秒制限は、3〜5秒の音を単純に置換すると途中で切る。映像イベントに同期させ、ポーズ／再開、途中で画面が閉じたときの終了、次の音との重なりを用途ごとに確認する。試聴を通ったことを本編の合格に拡張しない。

音の高さの確認では、FFTピークや帯域比だけで基音を決めず、[librosaスペクトログラムとpYIN比較](pitch-analysis.md)を使用する。推定不可は欠測として残す。
