# パチンコ演出SEの定量設計

音の役割と時間変化をJSONで指定し、参照する既存演出の録音を入力音色へ移さずに合成する。音量や層の数だけで迫力を代用せず、衝撃・本体の変化・保持・余韻の配分を設計する。

## 現在の制作・検証方針

参照音の再現では、まず全体を共通のシンセ・プリセットで鳴らし、音程・打点・音長を合わせる。音域ごとの自然な響きの差と、区間ごとの音色切替を区別する。音色を調整するときは共通プリセット全体を先に見直す。部品・手法を増やすことを改善と扱わず、区間別の倍音パレットや独立したノイズ・スイープを追加する前に、共通音色の一体感が失われていないか確認する。これは再現の出発点であり、別の役割のオリジナルSEへ同じ音色を一律に強制する規則ではない。

今回の参照実験は3例で改善を示せず、2例は旧方式より悪化した。制作機能が増えたことと、音の品質が上がったことを区別する。noise・tone・振動速度・音量カーブの追加は実験段階として扱い、既存の肯定された音へ一律適用しない。

既定では一音を対象に、基準音と設定を保存し、1つの変更軸から試す。原音・基準音・候補音を同条件で比較し、改善が確認できるまで別の音や共通処理へ展開しない。複数の制作を明示的に依頼された場合も、音ごとに比較と評価を分ける。複数を同時に作ったことが今回の失敗原因という仮説は未確定で、一般的な禁止規則にはしない。

音色、振動の質、音程の動き、入口、余韻のどこが違うかを具体化し、対応する変更だけを試す。現在のobjectiveは採否の基準に使わない。説明・資料・設定の更新だけを、音の修正完了や品質向上として報告しない。

## 役割と参照

新しい音の依頼が「派手」「気持ちいい」など曖昧なときや、合成・録音素材・生成サービスの使い分けを検討するときは、[音の設計票と制作方法の選択](references/sound-brief.md)を読む。役割・質感・空間・時間変化を制作前に具体化し、Hzの制御と区別して残す。

- 予告／役物／図柄確定／BONUS／RUSHのどのイベントに使うか決める。結果を知らせる時刻、待つ区間、収束する区間を秒で定義する。強い予告と当確の意味を混同しない。
- 参照がある場合、対象区間の波形・スペクトログラム・打点間隔・主な帯域の動きを確認する。声・BGM・録音処理が混ざる場合、測定値をSE単独の仕様と決めつけない。図の観察、聴感評価、設計上の提案を分ける。
- オリジナル化では、打点の構造、下降／上昇／保持の関係、倍音の開き方を翻案する。録音PCM・スペクトル係数・声を新音へ移さない。観察できない場合はその限界を明示し、独自の数値設計を出発点にする。
- silverball-chroniclesではプロジェクトのAGENTS.mdとweb-pachinko-designに従う。音の初稿制作を本番差し替えや公開の指示へ広げない。

## 参照による再現実験

ユーザーが参照の再現やスキル強化を求めた場合は、[再現実験の手順](references/reference-experiments.md)を読む。クイズ・解説付き資料なら、出題番号、最初の音、答え・解説、混在する声や背景を対応づける。全体の解説をSEへ混ぜず、比較対象を明示した区間へ固定する。

基準の合成→特徴を追加した合成→差の測定→同音量の試聴を行い、候補・変更値・未達点を残す。録音を入力音色として使わず、観察した音程・包絡などを制御値として合成する。参照にフィットした実験設定は、オリジナルの採用済みプリセットと分ける。数値の改善率を聴感の一致率へ読み替えない。聴感と指標の順位が一致しない場合は、ユーザーの比較判断を採否へ反映し、低い指標だけで候補を昇格させない。評価対象外の例は改善率や成功例の集計から除外する。

## 数値から生成

[設定仕様](references/design-schema.md)を読んで、用途に合う設定を作る。原型が必要なときだけ[3案のプリセット](assets/approved-presets.json)をコピーして編集する。

- `at_s`／`duration_s`：打点の開始、保持、抜け。短・短・長などの拍を同じ音の等間隔反復へ勝手に置き換えない。
- `pitch_hz`：層内の秒とHz。下降・段階的な上昇・一定音程を明示する。変更は当該カーブだけに行い、尺を無断で圧縮しない。
- `fm_index`／`fm_ratio`：硬さや非整数倍音の量。`flutter`は震動感、`detune_cents`は広がりの制御に使う。
- `noise`は帯域ノイズ、`tone`はsine／saw／squareの倍音音色。`am_rate_hz`は振動速度のカーブ、`amplitude_curve`は全層に使える時間ごとの音量カーブ。
- `gain`、低い芯、金属層、ノイズ層：役割に応じて配分する。低音や高音が多いという理由だけで実機らしいと判定しない。
- `attack_s`／`release_s`／`decay_s`：入口の輪郭と収束。長い余韻で次の打点を隠さない。

使用するPython環境のnumpy／scipyとFFmpegを確認する。プロジェクトの既存環境を優先し、必要なら作業用venvへ導入する。次の`<skill-dir>`はこのSKILL.mdがあるディレクトリ、`<python>`は依存を利用できるPythonへ置き換える。出力先には空の作業ディレクトリを指定する。

```sh
<python> <skill-dir>/scripts/render.py --design <design.json> --only <one-cue-id> --out <new-output-directory>
# 評価済みの複数案を明示的に再出力する場合
<python> <skill-dir>/scripts/render.py --design <design.json> --out <another-empty-directory>
# 合成しない設定検証
<python> <skill-dir>/scripts/render.py --design <design.json> --out <unused-directory> --validate-only
```

出力は48kHz stereo PCM24 WAV、256kbps MP3、連続比較WAV、周波数図、試聴HTML、解決済み設定と測定JSON。乱数seedを案ごとに初期化するため、同じ設定・エンジン・依存環境では、単独生成と複数案生成のPCMが一致する。設定とコードのSHA256、依存の版を保存する。

## 共通パルス音色・ハーモニーの選択肢

C方式の矩形波・鋸波や、同じシンセの2声を重ねるオリジナルを作る場合は、[評価された共通音色と2声の設計](references/pulse-harmony.md)を読む。Cと低いハーモニーの評価・確定設定を再利用の出発点にし、BのFM方式も選択肢として残す。今回の音程列や設定を全効果音へ一律適用しない。

## 測定と調整

[測定の意味と調整方法](references/measurement-and-tuning.md)を読み、`measurements.json`で確認する。

- 尺・チャンネル数・有限値・始終端の処理・PCMクリップ・true peakを確認する。生成スクリプトは不正な設定、範囲外のイベント、出力先の既存ファイルを拒否する。
- loudness目標とtrue peak上限の両方を記録する。既定の−18 LUFS／−2dBFSは今回の試聴用初期値で、ジャンル共通の正解ではない。固定ゲインで両立できなければピークを優先し、目標未達を報告する。リミッターで黙って埋めない。
- 帯域エネルギー比、スペクトル重心、crest、400ms RMS、モノラル化の音量差は比較の補助に使う。LUFSとRMSを同じ指標として扱わず、数値だけで音色や実機らしさを合格にしない。
- 同じ役割の案では、打点・音程変化・音色・余韻のうち変更する軸を絞る。必要な案数だけ作り、毎回3案を義務にしない。サンプルレート、ゲイン調整条件、比較の無音間隔は記録する。

## 音の高さを確認

音程の確認・調整では[librosa / pYINによる比較](references/pitch-analysis.md)を読み、参照音と制作音のスペクトログラムと基音の時間変化を比較する。探索範囲は対象音から決めて根拠を残す。推定できない区間を無理に数値化・補間せず、欠測と推定の限界を報告する。FFTピークの強さと基音、倍音による明るさを区別する。

## 試聴と引き渡し

silverball-chroniclesのユーザー指定（2026-10-11）では、以降の比較ページに出す音は参照音と最新候補の2音だけにする。基準・中間版は検証用に保存するが、比較プレーヤーへ表示しない。別の形式が新たに明示された場合はその指示に従う。

出力の`index.html`を既存のローカルサーバー、または作業ディレクトリのローカルHTTPサーバーで開く。ブラウザでWAV／MP3をデコードし、開始から終了まで再生できること、切替・停止、保存、必要な画面幅を確認する。ファイル読込や`ended`はスピーカーから聴いた証拠ではない。

耳で確認できる環境では、スマホのスピーカーとイヤホンで、入口の認識、最後の一打、低い芯、余韻、必要な頻度で繰り返したときの刺激を確認する。できなければ聴感未検証と報告する。承認済みの過去の音を、新しい設定の聴感受入へ流用しない。

本編への接続が依頼された場合だけ、既存の発音窓、ポーズ／再開、結果イベントとの同期、次の発音との重なりを確認して実装する。尺を変える場合は音だけでなく表示との関係を扱う。

返答には試聴ページと音声ファイルの入口、用途・尺・変更した数値の要点、確認した範囲を示す。仕様・設計・検証記録は対象プロジェクトの資料配置に従い、silverball-chroniclesではdocs/に置く。

## 復旧後の利用と後続のフィードバック

2026-10-16に履歴から復旧した版。合成・解析スクリプトと設定は同梱するが、元のPython環境・試聴サーバー・過去の音声ファイルが存在すると仮定しない。Pythonにはnumpy/scipy、測定にFFmpeg、音程解析にlibrosa/matplotlibが必要。環境の実パスを確認し、消えた `/tmp` のvenvへ依存しない。

オリジナル制作で共通パルス音色の2声を試す場合は `scripts/render_pulse.py --out <new-empty-directory>` が使える。汎用イベント列は従来の `render.py` を使う。

[後続の試聴フィードバック](references/session-feedback.md) を読み、ドラム・ベース追加や最後のフォールの解釈を採用済みと誤認しない。シンセ以外の制作を禁止しない。ユーザーが実音やドラム音源を求めたら、利用条件を確認した素材を使って出典・ライセンス・加工値を記録できる。既存機種の演出録音を製品へ転用することとは区別する。

今回の復旧確認はコードと数値の検証。以前の聴感評価は、その設定の過去の選好として保持し、復旧後の再生成音を新たに実聴取したとは報告しない。
