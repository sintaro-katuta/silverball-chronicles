# RUSH100回転・66%と専用当たり演出の確認

対象：初号機、強化なし。通常時は変更しない。

- RUSHは100回転以内に少なくとも1回当る確率が66%。1回転は `1 - 0.34^(1/100)`。外れても残回転を消化し、外れを理由とした即時終了や別の34%終了抽選はない。
- RUSH当りの払出振分けは1000玉30%、1500玉50%、3000玉20%。満額にはアタッカーへの規定入賞が必要。
- 通常の6倍拡大と分け、RUSHは短い斬撃・虹色の777で決着する確認案。SE・戦闘は未追加。

## 検証

`npm test`：212件成功。100回転を外し切ったときの終了、最終回転の当り、保留の引継ぎ、当り後100回転への復帰、通常設定の維持、各払出額の実入賞との一致を含む。`npm run build`成功。

動画は `lcd-rush-win.html` の実行を30fpsで収録し、当り付近と払出完了・復帰付近の2区間を抜粋する。当落だけは通常2回目とRUSH5個目の受付を当りにした確認系列。払出の振分けを1000玉等へ固定していない。物理の更新タイミング等により選ばれる払出は変わり得る。通常抽選確率の統計検証を動画に代用させない。

録画スクリプトは当り開始時の最大払出を保存し、終了時の実払出と照合する。1000/1500玉は100入賞、3000玉は200入賞。一時停止時の画面停止、ブラウザエラーなし、音声なしも確認する。詳細は `verification.json`。

`capture.mjs` で収録後、`python3 reference-review/pixi-rush-66/make-video.py` で `continuation.mp4` と確認用コマ一覧を生成する。

実録結果：RUSH当りで1500玉を選択。追加100入賞で1500/1500玉を達成し、RUSH残り100回・連数2へ復帰。ブラウザエラー0。`continuation.mp4` は26秒・音声なし。コマ一覧でも中央図柄の決着、斬撃、虹色の777、払出完了からRUSH復帰までを確認した。
