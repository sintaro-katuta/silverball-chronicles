# 保留追加・消化の表示

本作への提案：液晶下端の青銀色の保留を、追加時に10画素上から着地させる。消化開始時は抽選IDを保ったまま左の変動中位置へ移し、後続を詰める。移動は0.28秒、ゲーム時計に同期。期待度を示す色変化は追加しない。

参照：web-pachinko-design/references/visual-patterns.md の「保留は残数と対象の位置が分かる形」「変化演出が消費・追加を壊さない」。実機固有の演出の再現ではなく、本作への表示提案。

`capture.mjs` は lcd-rush.html のヘソ入賞→確認用の当たり→払出→RUSH100回→通常復帰を記録する。通常確率・入賞率の検証には使わない。ゲーム内の保留列そのものを参照し、表示のための保留追加・消費はしない。音声なし。

`hold-motion.test.js` は同数での入れ替わり、即変動、満杯、時計停止、モード変更、リセットを検証。抽選・保留上限・賞球・物理に変更なし。

検証完了：4テスト・ビルド成功。実動録画で100回消化・通常復帰、900玉払出、停止画像一致、ページエラーなし。`holds.mp4` は通常16秒／RUSH16秒／通常復帰5秒の37秒抜粋。途中の待ち時間を省略している。`motion.jpg` と `normal-motion.jpg` は録画の連続フレーム確認用。視覚の採用はユーザー確認待ち。
