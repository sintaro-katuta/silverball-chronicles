## 状態APIの合意

ルール担当の `Rules.BonusPresentation` / `IsBonusPresentationPending` を使用する。最後の入賞で払出が完了しても、Story→Result→Entranceの間はMode／Remaining／保留の消化を待機する。表示は`Phase`と`Elapsed`に追従するだけで、UIからモード変更・払出・抽選・終了命令を送らない。

- `CompletedAward` は完了した賞球情報、`Paid`は実払出。
- `Story`内は行先を読み出さず、`Result`以後にだけ成功／継続／通常復帰を出す。
- 通常BONUSと「決意の刃」はタイトルで区別。SWORD RUSH中の全BONUSを上位チャレンジ扱いにはしない。
- PUSHはルール側の末尾3秒に合わせる。入力で結果を変えない。
- ポーズ／倍速は共通ルール時計に従う。1回の大きいTickで次STを裏消化しないことはルール担当の検証対象。
- 完了snapshotは残るため`IsActive`で可視判定。旧追加3秒RUSHロゴは直接RUSH試演だけに限定し、通常遷移で二重に重ねない。
- `ReferenceBonusView.BlocksBasePresentation` をC担当へ渡し、物語中の通常図柄・保留・リーチ・上位画面の重複を防ぐ。

## 実装ファイル

- `ReferenceBonusView.cs`：待機状態との接続、基底表示抑制API、旧入口との二重再生防止。

- `BonusStoryView.cs`：各カット、円形人物マスク、刃／PUSH／巨大数字／Total、音キュー。

- `BonusStoryArt.cs`：新規制作素材を差せる任意受口（quinella / fallenAlice / driveIntroduction / driveResult）。現在これらの素材は未割当。
- `Editor/BonusStoryValidation.cs`：純粋なタイムライン検証。ルート誤分類、人物順、PUSH窓、早期行先、数値の単調性と実Paid上限を確認する。
