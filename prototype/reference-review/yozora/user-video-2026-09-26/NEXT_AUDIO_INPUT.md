# 担当8：音／操作感の未達台帳と静的レビュー

2026-09-26。対象はSAO Unity独立試作。`web-pachinko-design` の時間・音・役物の参照資料を読み、`YozoraSoundscape.cs` / `YozoraMachine.cs` / `ReferenceSequenceView.cs` / WebGLテンプレートを静的レビューした。R1/R2の音声・今回のWeb出力は実聴していない。コード上のキューやテレメトリを聴感品質・実機一致の証拠にしない。原音の抽出配布、音声動画のアップロードは行っていない。

## 静的レビュー結果と担当修正

1. **停止中のPUSH**：`Command("push")` は窓内判定のみで `Paused` を確認しない。停止中でもimpactを書き換え、キュー履歴が増える。親担当が`!Paused`の入力ガードを追加済み。
2. **起動前の音量入力**：WebGLテンプレートのrangeはロード中から有効。`unity=null` の間のsendは捨てられ、起動後もrangeは音量テレメトリに同期しない。画面の値と実音量の不一致が起こり得る。親担当が起動までの無効化と音量テレメトリ同期を追加済み。
3. **複数斬撃と音**：現行`Cue`はphase変化のみ。通常101秒と132/136秒のBeamは専用slash cueが出ず、108/128秒のみphase変化で鳴る。この指摘を受けて`YozoraSoundscape.ObserveAdditionalSlashes`を実装。通常101/132/136秒と右12秒をticket/elapsedの交差で一度だけ発音する。既存phaseの108/128秒は対象に入れず、右12秒の同フレームの汎用anticipation音は抑止して重ねない。
4. **PUSH連打と重複音**：窓内なら連打ごとにPlayOneShotする。静的レビュー時点では上限がなかったため、`PlayCue`に実時間150msの音だけの再生抑制を追加。PUSH入力の画面反応は維持する。Resetで抑制時刻も初期化する。
5. **起動済みの主経路**：ON/OFF、Pause/Resume、Reset、4/8倍の音源停止、1倍復帰の条件をコードで追跡。以前のResetミュート継続と高速での音重複は現行で対処されている。新たな重大な寿命管理/破棄漏れは見つからなかった。

音声クリップの生成数やキュー履歴は「発音要求」の記録であり、スピーカーから鳴ったという証拠ではない。最終確認は親担当のWeb動作記録と、別途の実聴記録を参照する。

### 今回の音コード変更

所有ファイル`YozoraSoundscape.cs`だけを修正。追加斬撃は新ticketで観測基準を作り、同ticketの各閾値をbitで一度限りにする。Pause中は進めず、OFF/4・8倍でも交差済みを記録して通常速度復帰時に古い音を再生しない。ResetCuesとticket終了で履歴を初期化する。音源の実機一致と実聴検証は未達のまま。PUSHガード・起動音量のUI修正は親担当が実施済み。
