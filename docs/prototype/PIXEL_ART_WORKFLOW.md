

# 液晶ドット素材の制作手順

2026-11-01、人物予告と復活突入の格子版に対するユーザーの評価を、今後のシーン制作で再利用するための記録。対象の仕様・演出に合わせて調整し、この寸法や方法を全画面に強制しない。

## 基準

- 通常画面の元絵 `prototype/public/assets/lcd/moon-castle-v1.png` を主人公の基準にする。銀髪、青い目、金の花飾り、紺と金の鎧、青いマント、剣を画面間で照合する。
- 他のシーンを作る際は、文章だけでなく、ユーザー評価済みの顔と全画面の画像自体を参照として使う。顔の基準画像は `prototype/reference-review/pixel-art-style-reference/hero-face-105x70.png`、背景を含む6カットは `prototype/reference-review/pixel-art-style-reference/hero-scenes-grid-105x70.png`。拡大比較用は `hero-scenes-grid-preview.png`。顔の編集用JSONは `hero-face-105x70.json`。全素材をコピーしたり構図を固定する指示ではなく、人物の同一性と格子・粒度・画風の参照とする。
- ドットは色で塗られた格子のマスとして扱う。鼻・眉・目だけ滑らかな細線にしない。人物だけでなく、同じ画面に見える背景の粒と比べる。画像の大きさだけでは判定できない。
- 人物予告は1カット105×70、6カットのシートは315×140、歩みは96色、他の予告と復活はそれぞれシート内で128色を共用した。液晶210×140に対して縦横2倍の基準例であり、戦闘の全身などにそのまま当てはめる仕様ではない。

## 作り方

1. 既存演出の構図、カット順、実際の表示領域、レイヤーの基準点と動き、音や結果との関係を確認する。ユーザー確認済みの主人公・画風を参照し、必要なら画像生成で構図の下絵を作る。
2. 表示領域を適切な画素格子に切り出し、最近傍で標本化する。各マスは一色とし、シート内でパレットを揃える。ぼかし補間を使わない。画像生成の出力をそのまま厳密なドット絵とみなさない。
3. 編集可能なパレットと各マスをJSONとして保存し、目・眉・鼻・口、髪や輪郭、手、剣などを原寸と補間なしの拡大で確認し、必要なマスを直す。`prototype/tools/pixel-workbench/face-study.html` と `index.html` は顔の編集用。構図や人物としての自然さも確認し、単に粒を大きくしただけで合格としない。
4. 表示側は該当素材をnearestで扱い、正しいカット範囲を使う。JSONとPNGの全画素・パレット一致、シートの寸法を確認する。生成元、参照、加工、個別修正、未検証項目を素材の `.prompt.txt` 等に残す。画像からの標本化とマス単位の手仕上げは区別して記録する。
5. 実際の画面で背景・人物・効果を合成し、拡大・縮小・移動・アニメーション中の粒、足元、透過縁、顔と手の読みやすさ、カット境界を確認する。素材が格子状でも、レイヤーごとの拡大率・回転・変形・効果によって最終画面の粒は揃わない。再生の入り・保持・抜け、一時停止、音と光の同期、PCとスマホ幅を対象に応じて検証する。

## 既存ツールと注意点

- 予告3列×2段の元画像からの標本化は `sample-step-frames.swift`、6カットの共通パレットとPNG/JSON生成は `build-memory-grid.mjs`。歩みは確認済み顔を保持する `build-step-grid.mjs` を使用した。
- 復活の2列×3段は `sample-entry-frames.swift` と `build-memory-grid.mjs` の列数引数 `2` を使用。元シートで表示時に削っていた余白を標本化時に取り除いているため、格子版に同じ余白カットを重ねない。鼻の修正例は `refine-revival.mjs`。
- スクリプトは既存素材向けの寸法・クロップ・出力先を前提とする。別のシートでは実際の構図とセルの並びを確認し、必要なら調整する。ソース画像やユーザーの編集済みJSONを上書きする前に出力先を確認する。
- 戦闘候補では、粗くしすぎると顔がつぶれ、背景の描き直しで足元の接地線もずれた。格子化だけで完成とせず、顔の識別と位置合わせを両立してから接続する。
- ユーザーは、代表例の方向を示した後は一つずつ確認を求めず、同じ品質を目指して全体を進めるよう指示している。工程中に自分で検証・修正し、成果と残課題をまとめて報告する。


通常画面の分離例：`prototype/public/assets/lcd/normal-hero-layer-v1.png` は元絵のRGBと二値マスク、`normal-background-layer-v1.png` は背後の補修を含む。人物の周囲に元の背景色が残る箇所があり、別の構図へそのまま転用できるとは限らない。格子化と元絵との合成差分、動作時の境界は別々に確認する。

戦闘の顔アップ：0.4.0の既存ポーズを維持して256×256の格子へ標本化した `hero-resolve-portrait-grid-v1.png` と全65536セルのJSONを保存。生成手順は `prototype/tools/pixel-workbench/build-resolve-grid.mjs`。顔の読みやすさと、人物・背景の表示粒度を本編で再確認する。
