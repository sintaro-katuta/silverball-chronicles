## 部品試作で決めた制作基準

- 既存の物理1単位を素材の2画素に対応させる。拡大領域256×320画素、最近傍補間、アンチエイリアスなし。画素への丸めは表示のみで、物理座標や速度は丸めない。
- 基準点はbonus口の中心 `(359,581)`、左端 `(329,581)`。画像左上の物理座標 `(294,510)`。素材の中に配置座標を隠さず `AttackerView.point()` に集約。
- ケース／奥面、既存ガイドレール、閉状態の扉、開状態の扉、玉の5テクスチャに分離。元の一枚絵の上に玉や扉を描き足していない。
- 銀・金・青の意匠を、金属・内壁ごとの明暗色を用いた画素プリミティブで直接制作。画像の縮小やモザイクではない。提供資料の装飾を簡略化した部品用原画であり、一枚絵の精密な切り出しではない。
- 描画順：奥面・固定装飾→球路→扉→玉→任意の照合線。ケースの意匠は非衝突の背面装飾。見える全線をコライダーとして扱わない。
- 玉の素材は19×19、中心アンカー。既存半径4.6を約9画素で表現。物理と画素丸めの最大誤差は各軸0.25物理単位。
- これはアタッカー試作の基準。全台・人物・小さいUI文字の解像度へ無条件に拡張しない。

## 初版の接続（v3の変更は末尾参照）

既存 `Physics` を `createPartFlow()` 経由で使用。元の発射位置・速度・重力・衝突・入賞横断判定を変更していない。玉は拡大領域の外にある実際の発射口から飛び、経路補間や画面内への瞬間投入はしていない。

固定刻み120Hzで物理を更新→同じ物理状態をPixiJSに渡す→一度描画。ゲーム更新は `startFrameLoop` が所有し、PixiJSの自動Tickerは停止。デモは5秒閉鎖、10秒開放、5秒再閉鎖。連続発射は最大10発/秒の既存部品テスト条件で、本編の発射速度設定ではない。

表示の扉は `Physics.updateGate` と同じ2状態。判定線表示をONにすると緑が入口高さ、赤が扉接触線と玉の中心。開閉・停止・発射を手動でも操作できる。フォーカス非表示時は試演停止。

抽選・賞球・ラウンド進行・プロフィール保存は行わない。開放中のfixtureは入賞10個で閉じる本編制御を再現せず、部品への取込みを連続確認する。

## 初版の検証と制約（履歴）

`../../../../prototype/reference-review/pixi-attacker/capture.mjs` で閉鎖時0入賞、開放時の入賞増加、再閉鎖後に増加しないこと、ポーズ中の状態不変、描いた扉端点と物理端点の一致を確認。結果は `../../../../prototype/reference-review/pixi-attacker/verification.json`。`tests/pixi-attacker.test.js` でも同じ物理の閉→開→閉を検証。本番ビルドに独立ページを追加。

**既存物理の制約**：閉時の接触線は `(329,596)→(389,579)`（長さ約62.36）、開時は `(329,581)→(329,608)`（長さ27）。基点も長さも変わるので、固定長の一枚扉を回転するだけでは一致しない。本試作では状態を即時交換し、独立した滑らかな補間を加えていない。連続開閉を作る際は、収納・複数部品の動きとして設計するか、接触状態の遷移仕様を別途検証する必要がある。

**今回の到達点**は、分割したドット絵素材が既存物理と一致して動く接続例。滑らかな開閉機構、一台全体、全演出の完成ではない。装飾密度は試作。音・スマートフォン実機の性能は未確認。クラウド更新なし。

## v3 開閉アニメーション

PixiJS独立試作に `attachAttackerMotion()` を追加。開放0.65秒、閉鎖0.5秒、smoothstep補間。ヒンジを上へ移しながら接触部を伸縮回転し、元の開閉端点に到達する。途中の逆操作は現在姿勢を出発点にする。固定ケースの外観はv2を保持。

試作のPhysicsインスタンスだけでupdateGateを拡張し、120Hzの更新で接触線と描画を同じ姿勢にする。開放完了で入賞許可、閉鎖指示で受付停止。これは動的ゲートの接触位置同期であり、モーターの力や挟み込みを厳密に解く機構物理ではない。本編Physics・抽選・賞球・ラウンド時間は未変更。

ポーズ・非表示では進行を停止。途中の逆転・端点への復帰・受付タイミングを `tests/attacker-motion.test.js` で検証。ブラウザ録画は今回再取得し、`../../../../prototype/reference-review/pixi-attacker/opening.png` は実動作途中。途中姿勢でも描画端点と物理端点の一致を検証する。上記の2状態切替・連続開閉未実装という記述は初版の履歴。

## v4 ユーザー意図に合わせた固定ヒンジ扉（現行）

v3の伸縮収納は不採用。四角い剛体板の下辺 `(329,608)→(389,608)` を固定軸に、上辺を奥へ90度倒す。cosで投影高さ、sinで奥行きと遠近の縮小を表現し、板面の装飾も同じ四頂点へ投影する。閉鎖時の上端は `(329,581)→(389,581)`、開放時の投影上端は `(333,600)→(385,600)`。ケース外観は維持。

試作の2D接触線は投影された上端へ同期。本編の物理は変更していない。これは3Dの剛体・挟み込みの物理再現ではなく、固定ヒンジの見え方と開閉・入賞接続の試作。開放0.65秒、閉鎖0.5秒、逆操作・ポーズ対応。動画と画像はv4で再撮影。

テストで10秒の実発射を行い、閉鎖中のアタッカー接触0・入賞0、下の坂への接触とOUT増加を確認。動画の閉→開→閉で取込みの切替を別途確認。ガイドの緑は入賞センサー、赤は下の坂と玉中心。試作限定で本編への適用はまだ行っていない。
