# PR冒頭動画の作成ルール

2026-10-09 ユーザー確定。次回以降のPRへ適用する。リポジトリの入口ルールは [AGENTS.md](../../AGENTS.md)、本文の雛形は [PRテンプレート](../../.github/PULL_REQUEST_TEMPLATE.md)。

## 必須の構成

PRの冒頭にRemotion＋VOICEVOXで作成したMP4をGitHub添付として置く。動画だけで、利用者の問題・変更前後・確認結果・残件が分かるようにする。無音でも要点が読める字幕を付け、音声と同期する。

| 変更内容 | 動画の説明方法 |
| --- | --- |
| 見た目の変更 | 同じ条件・演出秒の変更前／変更後の実プレイ映像を比較。入り・保持・抜けや必要な操作を見せる |
| 見た目を変えない変更 | 図解・表で処理や動作の前後、変更の効果、検証結果を説明 |
| 両方を含む変更 | プレイ映像の比較と図解・表を併用 |

細かな差には両側を同倍率で拡大して注釈を付ける。変更前を意図的に不利な設定・時刻・倍率で見せない。説明文字は顔・刀・ゲーム字幕・操作を隠さない場所へ置く。

尺は内容に応じて決め、今回の60秒を全PRの固定尺にはしない。動画の下に概要1〜2文、説明付き対象Issue箇条書き、検証結果・残件を簡潔に記載する。長い制作経緯・台帳・ログはリンクへ分け、コミットは目的別に分ける。

## 制作と受入

1. PMが対象Issue・説明範囲・比較条件を定め、Designerが場面と見せ方、Leadが対応するコード・検証結果を提出する。
2. 短い日本語台本を用意し、`yukkuri-video` スキルの人間承認を経てVOICEVOXで生成する。既定はユーザー採用済みのずんだもん・ノーマル（style 3）。別の声を指定された場合はその声を確認する。動画に `VOICEVOX:ずんだもん` 等の実採用クレジットを記載する。
3. 実WAVの長さを使ってRemotionの音声・字幕を同期する。比較に必要な時間が長ければ無言の保持を設け、音声と字幕を一緒にずらす。承認済みの発話を無断変更しない。
4. MP4を書き出し、Designerが字幕・主役・動きの視認性、SMが素材・対象head・生成物の対応、PMが説明内容と受入基準を判定する。
5. 実再生・受入後にPR冒頭へ添付し、GitHubの実プレイヤーでアクセスと再生を確認する。完了記録を保存してレビュー可能とする。準備中のPRはDraftとして扱う。

H.264/AACのMP4を使用し、添付しやすい10MB以下を目標にする。CLIで添付する場合は対応版の `gh pr edit --attach` を利用する。既存PRの本文と対象headを確認してから更新する。今回の制作・掲載例は [PR #16](https://github.com/sintaro-katuta/silverball-chronicles/pull/16)、[制作計画](pr16-video/PLAN.md)、[掲載記録](pr16-video/PR_PUBLICATION.json)。

## 証拠と説明の正確さ

素材と最終MP4のSHA、対象PR/headまたは検証ref、実コード・資産との対応、収録条件と受入記録を保存する。before/afterの機種・variant・保存結果・演出秒・viewport/DPR・表示設定・操作を揃え、fixtureと自然遊技、PC上のスマホ幅と実スマホを区別する。

録画の速度が違う場合は演出秒で同期し、編集・静止・速度変更・末尾保持を表示する。微小なfade差や欠測を隠さず、完全同期や自然FPSの測定とは呼ばない。既存画像を現在の変更の確認へ流用せず、動画が対象headを正しく説明していることを確認する。

動画内の検証済み・未検証・残件・公開状態は本文と一致させる。音声生成成功は人の実聴取やゲーム音の評価へ換算しない。公開状態や対象コードが変わった場合は動画の更新要否をPMが判断する。

このルールは対象PRへの説明MP4添付を許可する。本番ゲーム公開、CD有効化、Secrets操作への許可には拡張しない。

## 完了基準

- 動画だけで問題・変更前後・検証結果・残件が理解できる。
- 見た目変更は公平な実プレイ比較、その他は意味の分かる図解・表で説明できる。
- 音声と字幕が同期し、字幕や注釈がゲーム画面の重要部分を隠さない。
- 素材・対象head・最終MP4・PM判定を対応付けられる。
- PR冒頭に実プレイヤーが表示され、再生確認が済んでいる。
