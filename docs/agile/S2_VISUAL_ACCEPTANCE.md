# S2 #6：画質評価の条件と代表場面

S2 #6は計測と評価。最適化・新UI・素材の改変を無断で追加しない。`web-pachinko-design`とPixiJS performanceの「計測してから変更」を適用し、rAF計測・画質・実機・聴感を別に判定する。

## 同条件でそろえるもの

390×844/1440×900、DPR、canvas実寸、選択表示（盤面/液晶）、sourceとassets hash、同じ当落・図柄・演出variant・表示秒・cameraを記録する。測定時に#5CPU/録音/動画変換など別の負荷を混ぜない。rAFの30秒前後window×3回と、約3.4秒しか出ないPUSHのsubsamplesは分ける。PUSHを長く表示するために演出尺・表示時計を止めない。

| 代表場面 | 主役/画質を読む箇所 | 比較条件 |
|---|---|---|
| 通常待機/変動 | 図柄・保留、人物の目/髪、背景の水/雲、透過縁、玉 | 同じ図柄と同じ停止/変動位相。図柄の自然な動きは別の連続再生で評価。 |
| pressure戦闘24秒付近 | 顔・握り・刃の輪郭、字幕、カメラ寄りと背景 | same variant/当落/表示秒。顔と字幕を両方読める。全尺の迫力完成を静止画で認定しない。 |
| PUSH受付47秒付近 | ボタンの厚み/文字/光、顔との関係、字幕・刃 | 保存当落を公開前に漏らさず、外れ側にも同じ受付。3.4秒窓内で実表示。rAF計測は未操作の自動決着とし、実クリックは計測外の補助確認へ分ける。 |
| 公開済み右打ち/獲得 | 獲得文字/図柄、機構・透過、操作案内 | bonus専用入賞count/payout、mode、表示秒を記録。一般賞球を大当り獲得へ混ぜない。 |

## 判定軸

1. 顔・目・髪・刀・字幕・図柄が同じ場面で読め、pixel意匠やシルエットが保たれる。新しいにじみ、欠字、黒/灰色の透過残り、カット境界のちらつきがない。
2. 採用済みcamera/viewによるcropは維持する。液晶拡大で全身が入らないことだけを欠陥にせず、同条件の前後で重要部分が失われたかを見る。
3. PUSH・図柄・結果の意味/表示時刻、未告知の当落・復活前の敗北、保留/賞球を維持する。CPU/fpsが改善しただけで演出品質を合格にしない。
4. 390/1440のパネル/常設操作の欠けや重なりがない。動画・静止画を最新測定版で取得し、過去のS1/公開画像を今回の成功へ流用しない。
5. 前後比較候補がない初回計測なら「現行画質baseline」として提出し、最適化の画質保持検証が完了したとしない。PC/ブラウザDPRはスマホ実機のGPU/熱/長時間の証拠にしない。

Lead/rootがharness/測定画像を用意し、Designerは同条件画像と必要な連続再生を目視して合格/要修正/未検証を提出する。表示だけの固定fixtureと自然遊技を区別する。見た目が変わった再現問題は時刻・条件・最小対応をIssue候補化し、製品コードを独断で修正しない。

PUSH実クリックの補助は#7操作素材の同条件PNG/入力時刻を参照できるが、#7は390/DPR1の指定音fixtureであり、#6のDPR3性能windowとは別条件。実クリック未確認を#6 baselineの画質失敗へ混ぜず、表示/顔/文字/透過の評価と入力確認を別欄にする。

## 履歴参考：attempt01の静止画レビュー

2026-10-07、原workspaceの`prototype/reference-review/s2-2026-10-07/perf06/attempt01/390-normal-{1,2,3}-before.png`を`view_image`で目視。390×844/DPR3/液晶表示の今回の通常待機3枚。計測はSwiftShader環境であり、画像の読み取りと実端末fpsの判断を分ける。今回は静止画のみで、動画/録画など重い負荷を起動していない。

観察：371の3図柄、金/銀の縁、保留枠が読める。髪/衣装/刀のpixel意匠と人物の眼付近は確認でき、髪/枠に黒や灰の透過矩形は見られない。通常時は図柄が前景で、人物の顔下部は図柄に重なる現在の構図。戦闘で顔/字幕が読めるかの判定へこの通常画像を代用しない。液晶cameraのcropは採用表示範囲として扱い、上部装飾の顔が一部切れることだけを新欠陥にしない。

下部の持ち玉、発射状態、左打ち案内、発射停止、一時停止、強度0.20/sliderは画面内で判読でき、盤面との重なりなし。情報パネルは閉じた状態なので、展開時の欠字/操作評価は今回未検証。3枚とも通常静止の範囲で読み取り可能。

判定：390通常の現行画質baselineとして利用可能。最適化前後の画質保持合格、保存当落の動作確認、連続motion/fps、戦闘/PUSH/右打ち、1440、実端末、聴感はこの3枚だけでは未検証。製品改変を伴う修正提案は今回なし。

全28枚の確認範囲で黒/灰の透過矩形、新しい重要部分の欠け、常設操作との重なりは見られない。390の縦dock/1440の横dockは持ち玉/案内/一時停止/発射操作/強度0.20が画面内で読める。情報パネルは閉状態のため展開時の欠字/操作は今回未検証。

fixture限定条件：性能用private b.feed(false)は物理発射を止めるがmain UIのclosure feedingへ通知しない。実PUSH画像ではsnapshot.feeding falseに対しdockが発射中/発射停止のままなので、当該指定fixtureの物理/操作表示同期は未検証。自然遊技の製品不具合と断定しない。字幕補助は既存feed-toggleを実クリックして停止し、snapshot.feeding falseと画面「発射停止中」「発射開始」が一致している。自然発射中のsnapshotとPNGは非原子的取得（例stock379→378）なので、すべての値の同時一致を主張しない。

最終提出：現行runtimeの指定場面における静止画質baselineとして可。最適化は未実装であり、最適化前後保持の合格とはしない。連続motion/字幕fade全過程/保存当落の全動作、スマホ実機GPU/熱/長時間、聴感は今回の静止レビューscope外。rAFの性能判定はLeadの別計測結果へ委ねる。#7の実PUSHクリックは別DPR1補助、#7の人間聴感/hiddenは未検証のまま。計測中は録音/動画再生/decoder/別ブラウザを起動せず、今回レビューによる製品source/UI/assets変更はなし。
