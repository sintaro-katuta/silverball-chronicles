# パチンコ制作フロー

2026-10-15制定。SANKYOの記事を参考に、このプロジェクトの制作工程を定義する。新しい制作・改修は本書に沿って進め、対象と受入条件を決めるスプリント運用は継続する。

## 参照と適用範囲

参照：[SANKYO「パチンコ遊技機ができるまで」](https://www.sankyo-fever.co.jp/corporate/specialbook/process/)（2026-10-15閲覧）。記事は商品企画、デザイン、機構設計、電子演出、品質管理・検査、特許出願、販売・営業、広告・宣伝、製造・納入を紹介している。映像・音・光・役物を統合し、発生タイミングを調整する考え方を制作へ取り入れる。

以下の工程、成果物、判定条件は、このWeb作品向けの定義である。記事に掲載されたSANKYOの社内承認手順や開発日程を再現したものではない。

| 記事の仕事 | この作品での対応 |
|---|---|
| 商品企画 | 遊技体験の目的、対象、守る仕様、受入条件を決める |
| デザイン | 盤面・図柄・液晶の構図と絵コンテを作る |
| 機構設計 | 表示輪郭・接触・可動範囲と部品構成を試作する |
| 電子演出 | 抽選結果の保持と、映像・音・光・役物の同期を実装する |
| 品質管理・検査 | 機能・見た目・聴感・連続遊技・復帰・負荷を確認する |
| 特許出願 | 参照素材とオリジナル素材の出所を記録する。出願は制作の必須工程にしない |
| 販売・営業、広告・宣伝 | 試遊のフィードバックと、変更を説明するPR動画へ対応づける |
| 製造・納入 | 検証した版のビルド・集約・公開後確認へ対応づける |

素材の出所記録は、この作品での対応づけであり、特許調査や権利処理の完了を意味しない。

## 制作の順序と各工程の出口

流れは **企画 → デザイン試作 → 構造試作 → 統合試作 → 品質確認 → 受入・PR → 公開・フィードバック** とする。デザインと構造は互いの結果を見て修正する。失敗があれば原因の工程へ戻り、代表一本を通しで確認してから他の演出へ展開する。

| 工程 | 作るもの・確認すること | 次へ進む条件 |
|---|---|---|
| 1. 企画 | 誰がどの場面で何を楽しめるようにするか、対象、変更しない仕様、比較基準、受入条件 | 今回の目的と変更範囲が明確で、実装・試射の開始範囲が合意されている |
| 2. デザイン試作 | 盤面は同倍率の全体・対象部位、演出は粗い絵コンテと秒単位の構図。主役・伝える情報・まだ見せない情報を記す | 世界観と情報の優先順位が分かり、前後の差と評価方法を確認できる |
| 3. 構造試作 | 盤面の表示と接触の共通形状、部品の前後関係、可動範囲、素材・描画層・終了時の片付け | 見た目と機能の両方が成立する。通過成功だけで形状一致を合格にしない |
| 4. 統合試作 | 代表一本に映像・図柄・文字・音・光・役物を組み込み、共通の演出時刻へ合わせる | 入り・保持・決着・抜け・通常復帰まで再生でき、当落や賞球が演出の都合で変わらない |
| 5. 品質確認 | 同条件の前後比較、関連機能の検証、自然遊技、停止・再開、負荷、必要な実聴取 | 各受入条件に証拠と判定がある。未検証と不具合を区別し、通しで成立する |
| 6. 受入・PR | 採用・差戻し・持越しの理由、説明動画、短いPR本文、目的別コミット | 対象PRで変更・結果・残件を確認でき、必要な動画・CI・レビューを終えている |
| 7. 公開・フィードバック | 検証済み候補の公開、公開後確認、試遊の指摘を次の企画へ戻す | 具体的な公開許可があり、同じ候補の反映と公開後の動作を確認している |

工程の出口は担当者が成果物を確認する判断点であり、各工程でユーザーへの再承認を要求するものではない。合意した範囲の実装・修正・検証は続ける。新しい対象への拡張、確定仕様の変更、公開、音声台本の承認など、既存ルールで別判断が必要なものだけを分ける。

## 実装前に決める内容

作業ごとに、次の制作票を計画またはIssueへ記載する。小修正では数行でよく、同じ内容の別文書を増やさない。

```markdown
目的：誰が、どの場面で、どう感じる／何が分かるようにするか
対象：変える演出・部品・動作
守る条件：変えない遊技仕様、形状、素材方針
基準：比較する版、設定、表示幅、演出秒／試射開始条件
試作：最初に通しで成立させる代表一本と、その理由
設計：絵コンテ／形状、素材、映像・音・光・役物の時間表
受入：見た目・機能・聴感・復帰・負荷の必要条件
比較の限度：候補数、選別規則、追加比較を行う条件
成果物：再生できる試作、前後比較、結果表、対象PR
現状：現在の工程、未検証、次に進むために必要なもの
```

演出の時間表には、開始・終了秒、主役、構図、図柄・文字、音の打点、光、役物、操作受付、終了後の状態を記す。素材単体の完成より、場面内で何を伝えるかと組み合わせた時の効果を先に評価する。音を仮置きした試作は仮音と記録し、聴感の受入へ流用しない。

盤面の改修では、元図の画素寸法、論理座標、推定したmm、実測値を区別する。形状を固定して釘を比較する場合、発射・球径・重力・反発・壁・口を途中で一緒に変えない。比較基準を変える必要が出たら、その理由を記録して基準と候補を同じ条件で測り直す。

## 分野の役割と引き渡し

| 役割 | 責任と引き渡すもの |
|---|---|
| PM・企画 | 目的、範囲、守る仕様、受入条件を揃え、結果の採否と持越しを決める |
| デザイン | 全体構図・部品形状・絵コンテ・素材・時間表を作り、実装後の前後映像で意図との一致を確認する |
| エンジニアリング | 形状と接触、抽選と演出の分離、同期、ロード・片付け・復帰を実装し、再生可能な代表試作を渡す |
| 検証・進行管理 | 版・条件・証拠・受入条件の対応を照合し、未確認と依存を整理する |

同じ人が複数の役割を担当してよい。役割の定義だけで別タスクへの連絡やエージェントの起動を行うものではない。制作時は共通の時間表と形状を使い、撮影・録音・測定中は対象ソースの変更や測定を乱す処理を避ける。

## 品質確認と差戻し

指定した演出の再生は、当落別の見た目・同期の確認に使う。自然遊技は入賞・保留・抽選・払出を含む通しの成立確認に使い、両方の結果を区別する。

- 演出：該当する通常・期待・当たり・外れ・復活を確認する。確定情報の出る時刻、図柄との一致、PUSH受付、途中停止と復帰、通常へ戻った後の残留を確認する。
- 盤面：同倍率の形状と、自然な球の通過・入賞・逆戻り・滞留・液晶侵入を確認する。入賞改善は短い試射による候補選別と、選別に使っていない条件での長い確認を分ける。
- 音：数値検証、ブラウザ再生、実聴取、本編での受入を分ける。連続発音・BGMとの重なりは必要な場面で確認する。
- 動作・負荷：対象に応じた回帰、停止・再開・画面離脱・終了、表示幅と負荷を確認する。PCブラウザの結果をスマホ実機の保証へ広げない。

結果には日時、対象版、条件、再生素材・ログへのリンク、合格・要改善・未検証、確認者を残す。過去の画像や成功ログを現在の版の検証として扱わない。

形が違えばデザイン・構造、タイミングが噛み合わなければ時間表・統合、当落や計数が違えば制御へ戻る。候補の限度に達して改善が得られなければ、基準を維持し、失敗した仮説と次に確認することを提出する。部分的な受入を台全体の完成へ広げない。

## スプリント・動画・公開との関係

[スクラム運用](SCRUM.md)と[スプリント計画](SPRINTS.md)は対象の合意・集約方法を、本書はその対象の制作方法を定める。固定週数を設けず、受入条件・検証・PM受入・集約PRのマージで終了する。3スプリント単位のリリース運用を維持する。

PRは既存のPR動画運用ルールに従い、冒頭のRemotion＋VOICEVOX動画で問題・変更前後・検証・残件を説明する。台本は合成前に人間承認を受ける。見た目の変更は同条件・同時刻・同倍率の実プレイで入り・保持・抜けを示す。動画が未完成ならDraftとし、実再生とPRプレイヤーでの確認を終えてからレビュー可能にする。

実装、試作の局所受入、本編への採用、releaseへの集約、本番公開は別の状態として記録する。クラウド更新・本番公開・CD有効化の既存許可条件は維持し、この制作フローの制定を公開許可へ拡張しない。
