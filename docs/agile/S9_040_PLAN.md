## 進め方と比較条件

1. 実装時に `release/0.4.0`、PR #71、Sprint 8の採用差分を確認し、統合済み基準のSHAを固定する。PR #71のOpen状態を集約済みと扱わない。原workspaceのHEADは今回 `6067384` で、未コミット変更も多いため、そのまま最新集約版として使わない。開発時は隔離した作業場所を用いる。
2. #40は通常外れと外れリーチを代表の対にし、同じ表示幅・設定・演出時刻で第一停止から復帰まで比較する。成立後に当たり・RUSH・専用停止へ確認を広げる。
3. 人物は #46 → #47 → #48 の順に進める。共通基準と参照素材の版を固定してから顔アップへ適用し、異なる基準の候補を混ぜない。工程ごとの開始再承認は求めず、技術・見た目の自己確認とユーザーの最終採用を区別する。Issueが求めるユーザー採用結果を未取得なら記録を残し、取得済みとは扱わない。
4. #48は「決意の一閃」を第一候補に、指摘場面を現行本編で同定する。顔アップと隣接カットを最初の代表一本とし、全戦闘の描き直しへ広げない。修正案はまず1案、追加比較は原因や実表示の不合格に根拠がある場合に行う。
5. PC 1440×900／スマホ幅390×844を比較の初期条件とし、全体・液晶の実表示倍率も記録する。静止画に加え連続再生、停止再開、非表示復帰、共有素材の利用経路、必要な回帰・ビルド・負荷を確認する。実機・実聴取を確認できない条件は未検証とする。

守る条件：抽選結果・確率・図柄配分・リーチ発生率・保留FIFO・賞球／払出・RUSH・チケット／保存、Sprint 8で採用する盤面条件を維持する。人物修正では演出尺、PUSH、音の打点、当落公開時刻を維持する。#40で表示列を直しても、保存された最終図柄の意味を変えない。高DPI・連続移動・補間の採用を粒度統一の名目で一括撤回しない。
