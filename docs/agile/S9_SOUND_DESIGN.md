# S9 音楽と効果音の初稿

2026-10-18。開始承認後、通常・戦闘・BONUS・RUSHのBGM4用途と、新SE8用途をオリジナルの数値スコアから制作しました。これは試聴・本編統合へ渡す初稿です。人間の聴感、ユーザー採用、本編への最終ミックスの合格を、合成完了やデコード成功から推定しません。

## 維持する採用方針

現行の明るい周期波シンセ、当たり−3半音・通常SE−2半音・高次倍音0.90の基準を尊重します。新SEもこの調律を使います。既存 `win` / `rushWin` の音程・識別リズム・尺・PCMは変更しません。保存当落・公開時刻・演出尺・PUSH・保留・払出・S8採用釘配置にも作用しません。

本編SEにドラムやベースを重ねた過去の不採用を、新BGMのリズム・低音まで禁止する規則へ拡張しません。好評だった低い2声ハーモニーは設計の参考とし、その音型を全用途へ流用しません。6.4秒の余韻試作や参照再現実験を採用済みとは扱いません。

BGMはSEスキルの対象外で、独立した旋律・和声・低音・リズムの作曲です。外部音源・サービス・録音・歌声は使っていません。写真や既存機種の録音から音を抽出していません。

既存の支え音 `presentation-atmosphere` は音楽ではありません。新BGMと無条件に二重再生せず、担当区間または置換を再生担当が決めます。既存の静けさ窓と結果公開境界は演出時計側で守ります。音源の曲長からゲームの演出時計を伸縮させません。

## 代表初稿の自己批評と検証の範囲

最初に `decisiveHit` と `normal` / `battle` を音源化しました。一撃初稿は旧音とピーク同等でも平均音量が約4.4LUFS低く、入口へ偏った構成でした。中間版を非公開履歴に残し、音高・尺を保って持続本体の長さ/配分/減衰を調整しました。最新v0は−17.06LUFS、旧音は−16.02LUFS、true peakは両者約−5.04dBTPです。スペクトルで入口の下降と本体・保持を確認しました。これは聴感で改善を認定した記録ではありません。

BGMはスコアに旋律・和声・リズムの別パートがあり、単なる持続パッドとの差を作っています。一方、通常と戦闘の密度・主題の識別性、戦闘の音域上昇、反復時の疲れ、スマホで低音が失われた際の拍の明瞭さは未聴取です。本編で重なるSEを含め、ユーザーが判断する必要があります。

全4曲・32新SE音型・9旧比較音をWAV/MP3へ書き出し、finite/ピーク/ステレオRMS/mono loss/相関、FFmpeg LUFS・true peak、MP3全デコードを測定しました。LUFS分析だけ末尾1秒を加え、出力ファイル自体は延長していません。測定は音楽性や聴感一致率の採点ではありません。複数音が重なるため混合F0を一音の音程とみなさず、指定Hz列をスコアに保存します。

比較ページへは各用途の基準と最新v0だけを表示します。v1〜3と中間版は内部検証に残します。平均音量差で判断を偏らせないよう、manifestの `auditionGain` は大きい側だけを減衰しLUFSを揃えます。原WAV/MP3は変更しません。旧パッド3秒と曲全尺は役割・長さが異なり、同一旋律の再現比較ではありません。

旧win/rushWinは保存した旧合成コードと現在の実装で、各4音型・48kHz左右PCMが全8件一致しました。新SE8用途の同入力再生成、カタログ尺とフレーム数、不正入力拒否も純粋チェック済み。ブラウザ再生・本編同期・人間のスピーカー/イヤホン聴感・ユーザー受入は別の状態で記録します。

## ソース・音源・再生成

音源API：

- `prototype/src/pixi/se/music-score.js`：`musicScore(name)`、`MUSIC_CATALOG`、`synthesizeMusic(name,rate)`。
- `prototype/src/pixi/se/s9-se.js`：`s9EffectDesign(name,variant)`、`S9_SE_CATALOG`、`synthesizeS9Se(name,variant,rate)`。
- `prototype/src/pixi/se/s9-synth.js`：決定的な周期波、発音、循環尾部とエコー。既存共通synth-waveは変更していません。
- `prototype/tools/s9-render-audio.mjs`：同じAPIのPCMからPCM24 WAV/MP3・測定・score・manifestを生成。
- `prototype/tools/s9-audio-spectrum.mjs`：同出力のHann2048/hop512・左右エネルギー和の帯域比と重心。Python環境への新依存なし。

```sh
# checkoutルートから。代表3音、または全音源を再生成します。
node prototype/tools/s9-render-audio.mjs
node prototype/tools/s9-render-audio.mjs --all
node prototype/tools/s9-audio-spectrum.mjs
```

試聴WAV/MP3：`prototype/reference-review/s9-20261018/audio-v1/{music,se,baseline}/`。`manifest.json` にID、対応基準、用途、loop/尺、固定試聴ゲイン、全ファイルSHA/bytes、実行ソースSHA・Node/FFmpeg版。`scores/` は全note/event列、`measurements/` と `spectral-measurements.json` は数値、`technical-checks.json` は旧当たりPCMと純チェックです。現時点は1つのローカル環境での再現で、別環境一般のbit一致を保証しません。

音源に使った録音・外部サービス・第三者作曲物はありません。参考にしたのは採用済み音色の方針と、SEスキルの設計票・測定・フィードバックです。外部への送信・本番公開・Git操作は行っていません。

## S9追加：リールとヘソ入賞（audio-v2）

2026-10-18 の追加承認で制作した5用途。既存4曲・先行8用途と採用済み win/rushWin は維持する。音の品質の人間聴取は未確認であり、数値・decode成功を聴感合格とは扱わない。音源は外部素材を使わない決定的な周期波合成で、ゲームRNG・当落・保留色を入力しない。

|---|---:|---:|---|---|
|spin|0.28秒|0.13|開始0/.08/.16秒の短い上昇。停止音より弱く、回転開始だけを知らせる|−30.32 / −17.72 dBTP|

設計上のHz（`SYNTH_TUNING.effectPitch`適用前）は、spinが329.63→392 / 392→440 / 440→493.88、左停止659.25→523.25＋329.63、右停止739.99→587.33＋369.99、中停止587.33→440＋293.66、入賞783.99→659.25＋523.25。実際の合成Hz・各層の開始/尺/gain/panは `audio-v2/scores/*-v0.json` が正本。4variantは固定倍率1/.994/1.006/.998であり乱数を使わない。

比較は用途ごとに旧基準と最新v0の2音のみ。入賞の基準は **「専用音なし（0.16秒の無音）」** で、架空の旧入賞音を作らない。リールは旧0.21秒との尺差を保ち、試聴gainは大きい方だけを減衰してLUFSを揃える。入賞の無音基準とは音量合わせをしない。短音のLUFSは解析用の1秒無音付加による補助値であり、素材自体には付加しない。

自己批評：長い尾と過度な高域は数値設計上避けたが、頻回入賞時の刺激、停止3音の識別と同時spinの重なり、実スピーカーでの小音の聞き取りは人の試遊で確認が必要。過去の明るいシンセの選好を、この新5音の聴感受入に流用しない。

制作物は `prototype/reference-review/s9-20261018/audio-v2/`。25 WAV（48kHz/stereo/PCM24）と25 MP3（256kbps）、設計票・LUFS/peak/mono/decode・STFT帯域/重心を保存した。無音基準のスペクトル/F0は定義しない。新5音は複数層なのでFFT重心を基音とは呼ばず、各層の指定Hzと分ける。耳での評価とブラウザー実再生は別工程。

再生成は `prototype/tools/s9-render-audio-v2.mjs`、帯域計測は `s9-audio-spectrum-v2.mjs`、既存保持照合は `s9-audio-v2-preservation.mjs`。出力先はaudio-v2固定・既存manifestがある場合は上書き拒否。再生成時は現在のaudio-v2を履歴ディレクトリへ保全し、空のaudio-v2へ元の `old-eight-pcm-before.json` を戻して実行する。音源制作の実行版はaudio-v2/executed-sourceに保存し、audio-v1は書き換えない。旧v1専用rendererを追加catalog付きの現sourceへ向けて再実行しない。

`preservation-proof.json` は、現合成と保存v1 WAVのPCM24（4曲＋8音×4variant、計36）を完全一致照合した。win/rushWin各4variantは保存済みfloatPCM SHAとも一致。v1全90音源ファイルのSHAも不変。生WAVはローカル保全・再生成対象、MP3/score/設定/測定/manifestをGit保持する既定方針を継続する。
